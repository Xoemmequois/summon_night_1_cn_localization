召唤之夜 (PS1 SLPS_025.42) 战斗界面数据解析
================================================
分析方式：PCSX-Redux (sstate9 = 战斗存档) 动态内存 + Ghidra 静态反汇编交叉验证
存档现场：ハヤト Lv.02 HP 052/052 MP 036/036，地图上 1 名玩家 + 2 名敌人。

地址约定：PSX 地址 0x801xxxxx；物理 RAM 偏移 = 地址 & 0x1FFFFF。


================================================================
一、战斗地图网格 (MAP GRID)
================================================================
基址        : 0x80099F78
单元格大小  : 0x10 字节
每行        : 0x200 字节 (32 格)
网格物理尺寸: 32 列 × 25 行 (FUN_80057748 清零时按 32×25 填 6)
活动地图尺寸: 由地图头决定，见 0xA6F3E / 0xA6F3F

单元格布局 (0x80099F78 + y*0x200 + x*0x10)：
  +0x00 u16  flags
              bit2 (0x0004) = 不可通行 (FUN_80060110 光标移动判定用 (cell & 4))
              bit1 (0x0002) = 临时标记
              bit14(0x4000) = 有单位占据
              bit0 (0x0001) = 起始点标记 (来自地图源 byte1)
              默认值 6 (= 0b0110, 不可通行)，见 FUN_80057748
  +0x02 u16  0xFFFF (默认/未用)
  +0x04 u16  绘制排序键 = 0x226 - (x + y) * 10   (等距画家的算法深度键)
  +0x06 u16  来自地图源 byte0 的高 3 位 (>>5)
  +0x07 u8   来自地图源 byte2 低 5 位
  +0x08 u8   地形高度 (来自地图源 byte0 低 5 位 & 0x1F)
  +0x09 u8   标记位 (FUN_80057800 中特定场景置 1)
  +0x0A u16  0
  +0x0C u32  占据该格的单位记录指针 (0x8009D3A8 + 索引*0x30)，无单位=0

相关初始化函数：
  0x80057748  网格清零：cursor=0，全部格 flags=6、+0x02=0xFFFF、+0x0C=0
  0x80057800  地图装载器 (参数=地图数据指针)：
               头 4 字节 { u8 width, u8 height, u16 baseHeight }
               之后 width*height 个 4 字节图块：
                 byte0: [7:5]=?  [4:0]=高度(5位)
                 byte1: flags (bit0=起始点, bit3=生成装饰物, 等)
                 byte2: [4:0]=?  [7:5]=?
                 byte3: [6:0]=动画/图形ID  [7:5]=模式
              写入 DAT_800a6f3e/3f(尺寸)、DAT_800a6f34/36(屏幕基准)、网格
  0x800541a8  单位占位：把单位写到网格 cell[+0x0C]、置位 0x4000，并调整 +0x04

地图尺寸/光标 (均为字节)：
  0xA6F3C u8  光标/选中格 X            (存档时=16)
  0xA6F3D u8  光标/选中格 Y            (存档时=3)
  0xA6F3E u8  地图宽度                (存档时=21 / 0x15)
  0xA6F3F u8  地图高度                (存档时=19 / 0x13)

摄像机滚动 (屏幕像素，传给 FUN_8002c3dc)：
  0xA6F38 s16 摄像机 X   (存档时 0x60，每移动一格 ±0x10)
  0xA6F3A s16 摄像机 Y   (存档时 0x88，每移动一格 ±0x08)
  0xA6F34 / 0xA6F36 = 地图基准屏幕坐标
  FUN_80057e90 写入；FUN_8005852c/80058340 做平滑滚动动画

光标移动函数 FUN_80060110：
  读 D-pad (FUN_80060310)，取目标格，若 (cell[+0x00] & 4)==0 则允许移动，
  更新 0xA6F3C/3D 并调用 FUN_800508ec(重算摄像机 + 刷新光标立绘)。


================================================================
二、战斗单位表 (玩家/敌人)
================================================================
基址        : 0x8009D3A8
最大条目    : 32 (0x20)
条目大小    : 0x30 字节
状态字      : 0xFFFF = 空/已死亡；0x8000 = 存在；其它位见下

条目布局 (0x8009D3A8 + 索引*0x30)：
  +0x00 u16  状态/标志字
              bit15(0x8000)=存在  bit14?  bit10(0x400)=激活/已布阵
              bit9 (0x200)=?  bit8(0x100)=?  0x8400 掩码常与 0x8000 比较
  +0x02 u8   单位自身索引 (FUN_80053bfc 写入 (char)slotIndex)
  +0x03 u8   类型/类别 (玩家=0；本战场敌人=0x5A；特殊值 0x37='7' 另见)
  +0x04 u16  ?
  +0x06 u16  标志位 (FUN_800609d0 检查 bit0；FUN_8005caa0 检查 bit6/0x40)
  +0x07 u8   阵营 0=玩家方  1=敌人方  (FUN_800607dc/80060848/800609d0 判定)
  +0x08 u8   所在格 X (tile X)   \  FUN_800541a8 读取用于占位
  +0x09 u8   所在格 Y (tile Y)   /
  +0x0A u16  ?
  +0x0C u16  动作标志 (FUN_8005caa0 检查 0x40/2；FUN_8005d2b8 检查 0x104/4/0x100)
  +0x16 u16  动画帧/计时计数 (FUN_8005d2b8)
  +0x1A u8   \
  +0x1B u8   /  FUN_80053bfc 从生成源拷贝
  +0x1C u16  /
  +0x1E..+0x28 6×u16 地图精灵/部件对象句柄 (本战场玩家=7,8,9,10,11,12；
              敌人1=13..18；敌人2=19..24，按序分配)
  +0x2C u32  指向 BattlerInfo 的指针

BattlerInfo 布局 (指针所指，HP/MP 所在)：
  +0x00 u32  角色/怪物 ID (玩家 Hayato=7；敌人=0x005A1E03 / 0x005A1F03)
  +0x04 u32  ?
  +0x08 u32  ?
  +0x0C u16  当前 HP      \  FUN_80060848 用 field_0x2
  +0x0E u16  最大 HP      /
  +0x10 u16  当前 MP
  +0x12 u16  最大 MP
  +0x14 4×u8 能力值
  ...

本存档 (sstate9) 实际内容：
  单位0 (玩家) : 状态=0x8000 索引=0 类型=0  阵营=0  格=(14,3)
                 ptr=0x800993F8  HP 52/52  MP 36/36
  单位1 (敌人) : 状态=0xC000 索引=1 类型=0x5A 阵营=1 格=(14,10)
                 ptr=0x80099B78  HP 44/44  MP 34/34
  单位2 (敌人) : 状态=0xC000 索引=2 类型=0x5A 阵营=1 格=(19,4)
                 ptr=0x80099BB8  HP 44/44  MP 34/34
  （单位3..31 状态=0xFFFF，空。地图上仅这 3 格 cell[+0x0C] 非 0）

单位相关函数：
  0x80053bfc  在表内找空槽并生成单位 (可选从源记录拷贝 0x30 字节)
  0x800607dc  统计存活敌人 (状态!=FFFF, &0x8400==0x8000, 阵营==1) → 敌全灭判定
  0x80060848  统计可行动玩家 → 我方是否还能行动
  0x80060964  统计某种"待处理"敌人 (掩码 0x8500==0x8100)
  0x800609d0  回合结束处理 (清 0x8000 位、变量0x14+1、刷新行动位旗标)
  0x80060bfc  战斗结束总判定 (调用上面几个，返回 0 = 结束)
  0x800608fc  查是否存在类型字节(+0x03)==参数 的玩家单位
  0x80060cc0  仅剩 1 个敌人时置位 0xA6F2C bit2 (自动战斗?)
  0x80055e74 / 0x80055f04  对单位状态字置位/清位 (0xFF00=全体)


================================================================
三、战斗场景装载与相关全局
================================================================
场景分派    : 0x8005d614 (按 param 查表 0x800156b0，0..0x5C)
场景存档缓冲: 0x80138000  (GetFreeSlot(baseAddress) 的 baseAddress，见 0x80033ed4)
  其中 GetSlotSubContent(slot, id) 取子块，GetSlotSubContentSize 取大小。
  FUN_80056e68 装载战斗场景：
    子块0 = 背景图 (FUN_8002bf58(0, 0x19, 0x230, ...))
    子块1 = 地图数据 → FUN_80057800   <-- 战斗地图来源
    子块2 = 某图 (FUN_8002bf58(3, id, 0x234, ...))
    子块3 = 装饰/物件列表 (类型0/1/2 → 各自贴图+动画)
    子块4/5 或 6/7 = 物件类型0/1 的贴图与动画
  装载后调用 FUN_80057e40(w/2, h/2) 把摄像机居中。

其它战斗全局 (基址 0x800A6F28 起)：
  0xA6F28 u16 战斗阶段/状态 (0=?, 1=?, 0x23~0x25 特殊场景)
  0xA6F2C u16 战斗标志位 (bit0=已初始化光标, bit2=自动, bit7=?/反向)
  0xA6F30 u16 ?
  0xA6F32 u16 当前操作方 (FUN_8006105c 与单位阵营比较)
  0xA6F40     地图基准高度相关
  0xA6F44     绘制范围
  0xA6F4C     界面模式
  0xA6F50/52/54/56/58  光标/单位/数字立绘对象句柄
  0xA6F5C/5E  物件类型0/1 的图片资源句柄
  0xA6F78     滚动动画状态机 (0..9, 见 FUN_80058b30)
  0xA6F7C/80/84/88/8C/90/94  滚动动画中间量
  0xA7080/82  玩家可用行动标志 (来自 BattlerInfo+2 == 0x28..0x2B，见 FUN_800609d0)


================================================================
四、与现有笔记的对照 / 修正
================================================================
- 战斗跳过解析.txt 的 0x8009D3A8 / 0x30 字节、阵营在 +7、BattlerInfo 指针在
  +0x2C、HP/MHP 均在 BattlerInfo 中，全部得到验证。
  其中 "第7字节(从0计)为1是敌人" = 记录 +0x07 阵营字节，正确。
  将阵营改为0会让该单位被 0x800607dc 判为"非敌人"，故敌全灭判定立即成立。
- 新增确认：单位所在格 X/Y 在记录 +0x08 / +0x09 (不是+0x0A)；
  状态字 0xFFFF 仅表示空槽/死亡，0x8000 表示存在。
- 0x8009D3D4 处 Ghidra 符号 PlayerInfo 实为单位0记录 +0x2C 的 BattlerInfo 指针
  字段，并非结构体数组首地址。
