================================================================
 Summon Night (PS1) — vblank 内存实时对话/黑屏文字提取指南
================================================================

【目标】
在程序运行任意时刻（vblank 轮询/内存 dump），仅凭内存读取即可获得：
  1. 当前是否在显示对话 / 黑屏文字
  2. 当前显示的文本内容（SJIS）
  3. 该文本所属的 FID（对话文件编号）
  4. 该文本在 FID 中的序号 INDEX（即 0x2013 指令参数、zh_CN key 后缀、TEXT:xxxx）

不需要对 Command2013_AddOneDialogLine 或任何指令加执行断点。

================================================================
 一、内存关键地址总览
================================================================

所有地址为 PSX 主存（2MB）地址。RAM dump 中文件偏移 = 地址 − 0x80000000。

地址            类型    含义
---------------  ------  -------------------------------------------------
0x80097cec      u16     对话显示状态机。值 1/2/3/4 = 对话激活，5 = 关闭
0x80097cda      u16     对话栏当前行数（c8fe0 表的有效项数）
0x80097cdc      u16     黑屏文字当前行数（c9000 表的有效项数）
0x800c8fe0[]    u16     对话行 → ring 缓冲索引表（当前对话页）
0x800c9000[]    u16     黑屏文字行 → ring 缓冲索引表
0x800c18b8[]    u32     行源指针数组（AddOneDialogLine 0x2013 累积，上限 100）
0x80097ba8      u32     实际行数 LineCount（AddOneDialogLine 计数，0 基；
                        每页/每段前由 FUN_80034190 清零）——纯内存定行数的唯一依据
0x8009eed0      结构体   ring 缓冲，42 项 × 0x168 字节/项
0x800A82CC      u32     ptrDialogContent，恒指向 0x800E8000
0x800E8000      byte[]  对话源缓冲（当前加载的 FID 全量内容）
0x80097ce0      u32     指向行源指针数组基址（黑屏时 = 0x800C18B8）

================================================================
 二、ring 缓冲结构（0x8009eed0，每项 0x168 字节）
================================================================

由 FUN_80035e6c（复制文本）与 FUN_80036e98/FUN_80037a6c/FUN_80037d8c
（逐字渲染）维护。一个 0x2013 指令 → 一次复制 → 一个 ring 项。

偏移    类型    含义
-------  ------  -----------------------------------------------------
+0x02    u16     打字进度计数（帧延迟计时）
+0x04    u16     该行显示延迟上限
+0x2e    u16[]   该行文本，按 16-bit 单位存储（SJIS 字符 1 单位），
                 0x0000 终止。0x4000 = @ 控制符，占 3 单位（+p1 +p2）
+0x7e    u16     当前已打字字符数（显示进度）
+0x80    u16     已绘出字符数
+0x164   u32     状态：1 = 正在逐字显示，0 = 显示完毕/空闲

注：+0x2e 的文本是 CM1100 编码原样拷贝。0x40 控制符需连带解析后
2 单位（3 单位一体），与 rip 时 @n 处理方式一致。

================================================================
 三、判别：对话 / 黑屏 / 无文字
================================================================

  黑屏文字激活：0x80097cdc > 0
  对话栏激活：  0x80097cec != 5 且 0x80097cdc == 0（值 1/2/3/4）
  无文字：      ceC == 5 且 cdc == 0

  【经验值】
    talk_ram（对话）：        state=3, cda=4, cdc=0
    black_talk_ram（黑屏）：  state=4, cda=4, cdc=10

================================================================
 四、提取流程（vblank 轮询可用，全内存读取，无断点）
================================================================

步骤 1：判别类型
    cdc = u16@0x80097cdc
    cda = u16@0x80097cda
    if cdc > 0: mode=黑屏,  ringTab=0x800c9000
    else:       mode=对话, ringTab=0x800c8fe0

步骤 2：读取实际行数
    n = u32@0x80097ba8        ← 行数 = LineCount（AddOneDialogLine 计数）
    注意：cda（对话）/cdc（黑屏）是窗口槽位容量（对话固定 4 格、黑屏
    10 格，含空位），不是实际行数；ce4 是“当前显示到第几行”。
    4 个真实 dump 验证：LineCount 与 c18b8 连续有效源指针数严格相等
    （typing=3/finished=3/talk_ram=3/black=5）。

步骤 3：读取各行文本（打字中也可读）
    方法 A（推荐，纯内存、不受打字进度影响）
        for i in 0..n-1:
            ptr = u32@(0x800c18b8 + i*4)     // 源字符串地址，显示期不变
            text = SJIS@ptr（读到 0x0000）
    方法 B（ring 缓冲，附打字进度）
        for i in 0..n-1:
            ringIdx = u16[ ringTab + i*2 ]   // 注意打字中 c8fe0 尚未填满
            entry   = 0x8009eed0 + ringIdx * 0x168
            text    = u16 流 @ entry+0x2e
            typed   = u16 @ entry+0x7e       （已打字字符数）
        打字中 c8fe0 可能还是全 0（4 槽指向同一 ring[0]），只用作
        显示进度参考，不作为行数来源。

步骤 4：求 INDEX（文本在 FID 中的序号）
    INDEX 定义 = 0x2013 指令参数 = CalculateDialogLineAddress(param)
              = zh_CN key 后缀 = ruby TEXT:xxxx

    方法 A（推荐，纯内存）：源指针反查 offsets 表
        ptr  = u32@[0x800c18b8 + i*4]         // 该行源字符串地址
        rel  = ptr − 0x800E8000               // 源缓冲内字节偏移
        word = rel / 2                        // word 偏移
        在 offsets 表（0x800E8000 起始 ushort[N]）中找 k 使
        offsets[k] == word  →  INDEX = k

    方法 B（直接读命令流 INDEX，Ghidra 确认）：
        Command2013_AddOneDialogLine@8001d598 原文：
          s0 = 0x800A8280                     // 命令系统上下文
          v0 = u16@0x800A8282                  // GlobalScriptContextPC
          v1 = u32@0x800A82BC                  // ptrCommandBaseAddr = 0x800E000C
          v0 = cmdBase + GlobalScriptContextPC*2
          a0 = u16@(v0 + 2)                    // ← 0x2013 指令的立即参数 = INDEX
        即：INDEX 作为 0x2013 指令的第二字（param）静态存在于命令流
        0x800E000C 基址中的某条 0x2013 指令后 2 字节。
        实测（dialog_typing 命令流）：
          0x800E2B98: 0x2013 0x0078   ← 120
          0x800E2B9C: 0x2013 0x0079   ← 121
          0x800E2BA0: 0x2013 0x007A   ← 122
        但 0x2013 是立即执行指令，执行完 PC 即前进到翻页指令（如
        0x2012）；GlobalScriptContextPC 只在「正在执行到指令」时指向
        它。因此 vblank 轮询时 PC 通常已不在 0x2013 上，需：
          · 回溯命令流：从 `cmdBase + PC*2` 向回扫，取最近一段
            0x2013 的 param；或
          · 直接读 c18b8 反查（推荐方法 A）。
        INDEX 对应地址链（已验证）：
          param=0x78 → offsets[0x78]=0x306 → 0x800E860C → せんぱぁい！
          param=0x79 → offsets[0x79]=0x30D → 0x800E861A → ちょっと、ちょーっと
          param=0x7A → offsets[0x7A]=0x318 → 0x800E8630 → 待ってくださいよぉ！

    注意：offsets[0] = N（既是字符串数量，也常被当作第 0 个空串的
    位置）。实际文本通常从 index 1 起。INDEX 存储区（命令流与 c18b8）
    在对话显示期间不随打字进度改变；改变的只是 ring 缓冲的 +0x7e
    进度与 c8fe0 填充度。

步骤 5：求 FID（对话文件编号）
    FID = 使 (subcontent id = FID + 0x29) 的 CM1100.DAT_{id} 内容
          与 0x800E8000 起始字节匹配。
    简单做法：取 0x800E8000 头部 4~8 字节，与 rom/CM1100.DAT 按
    GetSubcontent(id)（id=0x10+id*4 取 sector 偏移+长度）提取的各
    subcontent 逐一比对，命中者 id 即 FID+0x29。

    等价关系：FID = subcontent编号 − 0x29 = ruby scriptXX_fidXX 的编号
              = zh_CN key 前缀（0001..0145）

      0x800E2B98: 0x2013 0x0078   (120)
      0x800E2B9C: 0x2013 0x0079   (121)
      0x800E2BA0: 0x2013 0x007A   (122)

【LineCount 与 c18b8 有效指针一致性（4 个真实 dump）】

  dump                LineCount   c18b8有效指针   ce4   cdc
  ------------------  ----------  -------------  ----  ----
  dialog_typing       3           3              0     0
  dialog_finished     3           3              4     0
  talk_ram            3           3              4     0
  black_talk_ram      5           5              0     10

  → 结论：行数必须以 0x80097ba8 为准，不能使用 cda/cdc。

================================================================
 六、操作注意事项
================================================================

1. PSX 主存 2MB，dump 文件偏移 = 地址 − 0x80000000。
2. 所有 16 位值均为小端。取读时务必先提升为 int 再移位
   （PowerShell 中 byte -shl 8 会截断，曾导致误读 offsets 表）。
3. FID 源缓冲基址固定在 0x800E8000（ptrDialogContent 值恒为其址，
   由 InitializeCommandSystem 写入 0x800A82CC）。
4. 黑屏与对话共用同一源缓冲与 offsets 表，仅 ring 索引表不同：
   对话 c8fe0 / 黑屏 c9000。
5. c9000 表项可能多于实际填充行（黑屏 dump 中 10 项仅 5 行有文本），
   空行文本为空，属正常。
6. 打字中 c8fe0 可能仍为全 0（4 槽指向同一 ring[0]），因此行文本/
   INDEX 必须以 c18b8（源指针）+ LineCount(0x80097ba8) 为准。
7. INDEX 反查时 offsets 表可能出现“同 word 对应多 index”的重复文本
   场景（同一台词被多条 0x2013 引用），此时需结合行指针或 ring 顺序。
