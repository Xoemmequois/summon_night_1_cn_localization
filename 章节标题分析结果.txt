# CM2000.DAT 偏移 0x6CA — 8bpp 纹理 + tilemap 图层描述符

## 总览

Sector `0x6CA` — byte `0x6CA × 0x800 = 0x365000`，连续 17 个 sector（0x8800 字节），被游戏加载到
RAM `0x80110000`。最终在 320×240 屏幕上铺一层 16×16 纹理 tile（atlas 128×256，
tilemap 20×15），由 `FUN_8002ca28` 解码并绘制。

---

## 顶层结构（16 字节头）

文件 offset `0x365000` 开始，按 u32 读：

| 偏移 | 值 | 说明 |
|------|----|------|
| `+0x00` u32 | `0x0000_0091` | flags: `&7==1` → 16×16 tile; `&0x10==1` → 8bpp; `&0x100==0` |
| `+0x04` u32 | `0x0000_0010` | CLUT 在本块内的偏移量（`base + 0x10`）|
| `+0x08` u32 | `0x0000_0214` | atlas 图像在本块内的偏移量（`base + 0x214`）|
| `+0x0C` u32 | `0x0000_8218` | tilemap 在本块内的偏移量（`base + 0x8218`）|

---

## 1. CLUT — `base + 0x10`（256 色 RGB555 调色板）

| 偏移 | 类型 | 值 | 说明 |
|------|------|----|------|
| `+0x00` u16 | `0x0100` = 256 | 条目数（=256 → 8bpp） |
| `+0x02` u16 | `0x0001` = 1 | 行数 |
| `+0x04` 起 | u16 × 256 | RGB555 条目（每 16 位：B[14:10] \| G[9:5] \| R[4:0]）。entry 0 为关键色 = 透明 |

---

## 2. Atlas 纹理 — `base + 0x214`（8bpp，128×256）

LoadImage source = `base + 0x218`（头两个 u16 之后）。

| 偏移 | 类型 | 值 | 说明 |
|------|------|----|------|
| `+0x00` u16 | `0x0040` = 64 | VRAM word 宽（→ 8bpp 128px） |
| `+0x02` u16 | `0x0100` = 256 | 高（px） |
| `+0x04` 起 | byte × 0x8000 | 128×256 8bpp 像素，行优先 |

**加载方式**：`LoadImageToRect(param_1=0x17, 0, y, &ptr)` → `LoadImage(RECT(448, 256, 64, 256), ptr+2)`。  
tpage 坐标：`rect.x = 448 = 7×64`，`rect.y = 256 = 16×16`。

**用途**：封装 8×16 枚虚拟 tile（tile 即 atlas 16×16 栅格位置），在下面 tilemap 的 UV 字段中引用。

---

## 3. Tilemap — `base + 0x8218`（300 条目）

被 `FUN_8002c068` 拷贝到工作缓冲 **`0x801c8000`**（从 `PTR_DAT_8008dd50[0]` 获取），
行跨步 0x80 字节。

### 3.1 头部

| 偏移 | 类型 | 值 | 说明 |
|------|------|----|------|
| `+0x00` u16 | `0x0014` = 20 | 栅格宽（tile 数） |
| `+0x02` u16 | `0x000F` = 15 | 栅格高（tile 数） |
| `+0x04` 起 | u16 × 300 | tilemap 栅格自身（逐行排列） |

### 3.2 条目格式（u16）

解码（`FUN_8002ca28`，uVar3 取值后）：

看 **bits**：

```
bit  15      14:10         9:5              4:0
┌─────────┬──────────┬────────────────┬─────────────┐
│ valid(1)│ V 页高位  │ V index (×8)   │ U index (×8)│
│  0x80 -  │    (附加 tpage)      (总是偶数)     (总是偶数)  │
└─────────┴──────────┴────────────────┴─────────────┘
 位15=1   位14-10         位9-5            位4-0
```

  - **U_texel** = `(entry & 0x1F) × 8` （→ 0, 16, …, 112，与 128px 宽度对齐）
  - **V_texel** = `((entry >> 5) & 0x1F) × 8` （→ 0, 16, …, 240，与 256px 高度对齐）
  - **tpage 增量** = `(entry >> 10) & 0x1F` （V ≥ 256 时用；此处恒为 0）
  - **valid** = bit15 → `0x8000`=可见，`0x0000`=不画

U index 和 V index 总是偶数：tile 尺寸即 16px，编码的最小步长为 8px，低 1 位用不上。

## 4. 渲染管道

以下均在 `SLPS_025.42` 内：

| 函数 | 地址 | 角色 |
|------|------|------|
| `FUN_8002bf58` | `0x8002bf58` | 初始化图层描述符 `DAT_800be660`（视口 320×240、分配缓冲、设颜色） |
| `FUN_8002c068` | `0x8002c068` | 解析 16 字节头；加载 CLUT（`LoadCLUT_`）；加载 atlas（`LoadImageToRect`→`LoadImage`）；拷贝 tilemap 到 `0x801c8000`；填 tile 尺寸、行列数 |
| `FUN_8002be28` | `0x8002be28` | 每帧层调度器；读取 `DAT_800be662`（type=`flags&7=1`）→ case 1 进入 16×16 tile 渲染 |
| `FUN_8002ca28` | `0x8002ca28` | 核心渲染：遍历 20×15 栅格，每个非零条目解码 UV + tpage，发射 16×16 精灵到 OT |

`FUN_8002ca28` 的关键循环：

```
for (row=0; row<15; row++) {
    for (col=0; col<20; col++) {
        uVar3 = *(ushort*)(tilemap + row*0x80 + col*2);
        if (uVar3 != 0) {
            U = (uVar3 & 0x1F) << 3;
            V = ((uVar3 >> 5) & 0x1F) << 3;
            tpage = base_tpage + ((uVar3 >> 10) & 0x1F);
            draw_sprite(col*16, row*16, U, V, 16, 16);
        }
    }
}
```

---

## 5. 重建图

将上述逻辑展开：

1. 读 CLUT（256 色，RGB555）。
2. 读 atlas 128×256 8bpp 像素。
3. 读 tilemap 20×15 ushorts。
4. 对每个 tilemap 格子 `(row, col)`：
   - `entry = 0` → 跳过。
   - 否则取 `U = (entry & 0x1F) << 3`、`V = ((entry >> 5) & 0x1F) << 3`。
   - 从 atlas `(U, V)` 拷贝 16×16 像素到目标画布 `(col×16, row×16)`。
5. 目标尺寸 320×240（20×16 × 15×16）。

---

## 备注

- PS1 VRAM 为 16-bit/word；本数据为 8bpp。**UV 本身以 texel 为单位**（见上文条目格式，U/V 是 texel 偏移），GPU 通过 tpage 知道色深并自行寻址。

- 每个条目的 U index/V index 都是偶数（已验证，300 个条目无一例外）。

- Tilemap 工作缓冲 `0x801c8000` 在 PS1 RAM 内（`PTR_DAT_8008dd50[0]`），行步长 0x80 字节，适合 DSP/OT 直接检索。

- 本 arc 的 `flags & 0x10` 配合 `FUN_80029ba8` 生成 8bpp tpage，与 CLUT（256 号）和 atlas（128-wide）保持自洽。
